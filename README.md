# Контрольная работа №2 по Фронтенд и бэкенд разработке

## Практические №7-8: Аутентификация и JWT

**Цель:** Добавить систему регистрации и входа с использованием JWT токенов.

**Что сделано:**
- Хеширование паролей с bcrypt + соль
- Регистрация новых пользователей (email, имя, фамилия, пароль)
- Вход с выдачей access-токена (срок действия 15 минут)
- Middleware для проверки JWT в защищенных маршрутах
- Защита всех маршрутов товаров (только для авторизованных)
- Эндпоинт `/api/auth/me` для получения данных текущего пользователя
- Swagger документация для всех новых эндпоинтов

**Запуск сервера:**
`cd praktika7-8/server`  
`node app.js`

---

## Практическая №9: Refresh-токены
**Цель:** Реализовать механизм обновления токенов без повторного ввода пароля.

**Что сделано:**
- Генерация пары токенов при входе (access + refresh)
- Refresh-токен живет 7 дней, хранится в Set на сервере
- Эндпоинт /api/auth/refresh для получения новой пары токенов
- Автоматическое обновление токена на клиенте при истечении access-токена
- Интерсепторы axios для обработки 401 ошибок и повторных запросов
- Сохранение токенов в localStorage
- Эндпоинт /api/auth/logout для удаления refresh-токена

## Практическая №10: Хранение токенов на фронтенде
**Цель:**  Организовать безопасное хранение токенов и автоматизацию запросов.

**Что сделано:**
- Страницы входа и регистрации на React
- Автоматическая подстановка токена в заголовки всех запросов

- Выпадающее меню с информацией о пользователе и кнопкой выхода
- Обработка ошибок при входе/регистрации
- Защита маршрутов через PrivateRoute компонент

## Практическая №11: Управление доступом на основе ролей (RBAC)
**Цель:** Реализовать систему ролей с разграничением прав доступа.
**Что сделано:**

- Четыре роли: гость, пользователь, продавец, администратор
- RoleMiddleware для проверки прав доступа к эндпоинтам
- Предустановленный администратор при запуске сервера
   
*Админка для управления пользователями:*

- Просмотр списка пользователей
- Изменение роли (пользователь/продавец/админ)
- Изменение статуса (активен/забанен)
- Удаление пользователей

*Разграничение прав для товаров:*  
- Просмотр: все авторизованные пользователи
- Создание/редактирование: только продавцы и админы
- Удаление: только админы

*Интерфейс адаптируется под роль пользователя:*  
- Продавец видит кнопки добавления/редактирования
- Админ видит пункт "Управление пользователями" в меню
- Забаненный пользователь получает предупреждение при входе
- Полная Swagger документация для всех новых эндпоинтов
