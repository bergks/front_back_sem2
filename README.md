## Практические №7-8: Аутентификация и JWT

**Цель:** Добавить систему регистрации и входа с использованием JWT токенов.

**Что сделано:**
- Хеширование паролей с bcrypt + соль
- Регистрация новых пользователей (email, имя, фамилия, пароль)
- Вход с выдачей access-токена (срок действия 15 минут)
- Middleware для проверки JWT в защищенных маршрутах
- Защита всех маршрутов товаров (только для авторизованных)
- Эндпоинт `/api/auth/me` для получения данных текущего пользователя
- Swagger документация для всех новых эндпоинтов

**Запуск сервера:**
`cd praktika7-8/server`  
`node app.js`

## Практическая №9: Refresh-токены
**Цель:** Реализовать механизм обновления токенов без повторного ввода пароля.

**Что сделано:**
- Генерация пары токенов при входе (access + refresh)
- Refresh-токен живет 7 дней, хранится в Set на сервере
- Эндпоинт `/api/auth/refresh` для получения новой пары токенов
- Автоматическое обновление токена на клиенте при истечении access-токена
- Интерсепторы axios для обработки 401 ошибок и повторных запросов
- Сохранение токенов в localStorage
- Эндпоинт `/api/auth/logout` для удаления refresh-токена

## Практическая №11: Управление доступом на основе ролей (RBAC)
**Цель:** Реализовать систему ролей с разграничением прав доступа.
**Что сделано:**

- Четыре роли: гость, пользователь, продавец, администратор
- RoleMiddleware для проверки прав доступа к эндпоинтам
- Предустановленный администратор при запуске сервера
   
*Админка для управления пользователями:*

- Просмотр списка пользователей
- Изменение роли (пользователь/продавец/админ)
- Изменение статуса (активен/забанен)
- Удаление пользователей

*Разграничение прав для товаров:*  
- Просмотр: все авторизованные пользователи
- Создание/редактирование: только продавцы и админы
- Удаление: только админы

*Интерфейс адаптируется под роль пользователя:*  
- Продавец видит кнопки добавления/редактирования
- Админ видит пункт "Управление пользователями" в меню
- Забаненный пользователь получает предупреждение при входе
- Полная Swagger документация для всех новых эндпоинтов

## Практическая №13: Service Worker (Офлайн-приложение)

**Цель:** Реализовать базовый офлайн-функционал через Service Worker.

**Что сделано:**
- Регистрация Service Worker при загрузке приложения
- Кэширование статических ресурсов (HTML, CSS, JS, иконки, манифест)
- Стратегия Cache First для статики (мгновенная загрузка из кэша)
- Стратегия Network First для динамического контента (/content/*)
- Fallback-страница при отсутствии сети и кэша
- Автоматическое удаление старых версий кэша при активации
- Приложение полностью работает офлайн (просмотр и добавление заметок)

## Практическая №15: HTTPS + App Shell

**Цель:** Обеспечить безопасное соединение и мгновенную загрузку интерфейса.

**Что сделано:**
- Сгенерированы самоподписанные SSL-сертификаты через `mkcert`
- Настроен HTTPS-сервер на порту 3001
- Реализована архитектура App Shell:
  - `index.html` содержит только каркас (шапка, навигация, контейнер)
  - Динамический контент подгружается через fetch в `/content/`
- При первом посещении кэшируется весь App Shell
- При повторных визитах каркас отображается мгновенно
- Контент подгружается асинхронно с индикацией загрузки
- Полная офлайн-доступность интерфейса

## Практическая №16: WebSocket + Push-уведомления

**Цель:** Реализовать real-time обновления и push-уведомления.

**Что сделано:**

*Серверная часть (Node.js + Express):*
- WebSocket сервер на Socket.IO (порт 3001)
- Генерация VAPID-ключей для push-уведомлений
- Хранение активных push-подписок в массиве
- Эндпоинты `/subscribe` и `/unsubscribe` для управления подписками
- Рассылка событий `taskAdded` всем подключенным клиентам
- Отправка push-уведомлений при создании новых заметок

*Клиентская часть:*
- Подключение к WebSocket серверу
- Отправка события `newTask` при добавлении заметки
- Получение событий от других клиентов с всплывающими уведомлениями
- Подписка на push-уведомления через PushManager
- Кнопки "Включить/Отключить уведомления" с сохранением состояния
- Обработка разрешений на уведомления в браузере

*Service Worker:*
- Обработчик события `push` для отображения системных уведомлений
- Отображение иконки, заголовка и текста уведомления

## Практическая №17: Детализация Push (Напоминания и Snooze)

**Цель:** Добавить гибкое управление уведомлениями с возможностью откладывания.

**Что сделано:**

*Фронтенд:*
- Добавлено опциональное поле datetime-local
- Уникальный ID для каждой заметки (Date.now + random string)

*Серверная часть:*
- Хранилище активных напоминаний в `Map` 
- Планирование отправки через `setTimeout` с точностью до миллисекунды
- Эндпоинт `/snooze` для откладывания напоминания на 5 минут
- Отправка push-уведомлений с полем `reminderId` для идентификации

*Service Worker:*
- Кнопка "Отложить на 5 минут" в push-уведомлении (`actions` + `requireInteraction`)
- Обработка клика по кнопке с отправкой POST-запроса на `/snooze`
- Отображение подтверждения при успешном откладывании

# Установка зависимостей

# Генерация VAPID-ключей (если нужно)
npx web-push generate-vapid-keys

node server.js
